# B27b 验收记录：任务提醒升级与站内通知

## 范围

B27b 实现 B21 Work 任务的耐久提醒 occurrence 和仅站内的 `Notification` 收件箱；不实现 B27c 的邮箱、webhook、偏好、端点、provider outbox 或任何外部投递。

## 已实现边界

- `WorkTaskReminderPlan` 最多 8 个固定 `BEFORE_DUE`、`AT_DUE`、`OVERDUE` 步骤；目标仅可为当前责任人、创建人和关注人。非空计划要求开放任务具有截止时间；所有派生 occurrence `due_time` 与 `deadline_at` 均在写入前验证为 MySQL `DATETIME(6)` 的 1000–9999 范围，越界返回稳定领域规则错误；series 计划只复制到未来生成的任务。
- `notificationProjectionVersion` 与 worklist projection 分离：标题、优先级、责任人、关注人、截止时间、状态和计划变化推进前者；说明、评论、CRM 关系和附件不推进。任务变动先锁 task root，再撤销旧 `READY/LEASED` occurrence 与过时 inbox 投影。
- V69 使用 `(tenant_id, work_task_id, notification_projection_version, step_key)` 精确 occurrence identity；V70 为它加入有界 attempt/backoff/deadline、`RETRY_WAIT` 与 `DEAD/RETRY_EXHAUSTED` 终态。通知 purge、occurrence purge 与 claim 各自使用短事务提交，避免反转任务变更的 task → occurrence → notification 锁序。worker 以数据库 UTC 的独立 lease/fence claim 后按 task root → occurrence 顺序复核当前任务和步骤；lease 被截断到 deadline，最终 emitted 写入再次以数据库 UTC 验证 lease/deadline，才在同一事务中写入每收件人的唯一通知并结算 occurrence。过期租约逐行回收，失去 fence 不会结算，确定性失败不会无限重试。
- 收件人是当前任务参与者、活动成员并同时拥有 `notifications:read` 和 `work-tasks:read` 的交集。`crm_notification` 仅保存种类、任务 ID、标题/优先级/截止时间快照、状态和时间；SQL 在 count、分页和已读写入前重验当前成员与任务参与关系。已读写入首个数据库 UTC 时间且幂等。
- `OVERDUE` 仅产生 `WORK_TASK_ESCALATION`，不修改任务状态、优先级、责任人、Activity 或 worklist acknowledgement。只有过时的 `UNREAD` 投影撤回；已读行保留首个数据库 UTC read receipt。通知依配置的绝对上限按最早时间分批清理，随后仅清理无通知引用且已过时的终态 occurrence；当前开放任务的当前投影 occurrence 保留作为精确幂等证据。

## API 与运行配置

- `GET`/`PUT /api/v1/work/tasks/{taskId}/reminders`
- `GET`/`PUT /api/v1/work/task-series/{seriesId}/reminders`
- `GET /api/v1/notifications` 与 `POST /api/v1/notifications/{notificationId}/read`
- `atom.notifications.reminders.enabled`、`pump-concurrency`、`lease-duration`、`max-attempts`、`retry-backoff`、`retry-deadline`、`terminal-retention`、`notification-retention`
- `atom.scheduling.pulses-enabled`（默认 `true`）是统一的本地调度唤醒开关；它关闭时 enabled reminder lane 的 Actuator `notificationReminders` 报告 `SCHEDULER_DISABLED`。该指标还报告 `READY`、`DISABLED`、`CONFIG_INVALID`，以及 purge/claim/recovery 基础设施失败后、下一次成功前的 `RUNTIME_FAILURE`；`atom.work.task.reminders` 与 `atom.notifications` 仅以固定 outcome label 报告 lifecycle/inbox 计数。

## 验证

- WorkTask/WorkTaskSeries 域测试覆盖计划与独立 projection/generation 语义。
- `WorkTaskReminderIntegrationTest` 在 Spring 上下文创建前关闭 scheduled pulse，并在 MySQL Testcontainers 上执行 V69/V70：真实 reminder notification、并发已读、read receipt 保留、过期 lease 接管、deadline `DEAD`、通知先于 terminal occurrence 的留存清理、task → occurrence 并发锁序、stale pending 取消、成员/参与者/能力可见性、overdue 无 Work/worklist 副作用，以及 task/series 的 1000–9999 派生时间边界。
- 全量 fast Maven 测试及 Docker MySQL integration suite 是本批提交的验收命令。
