## 复审发现与处置

### 1. B18b 内部 tenant 不一致会被误报为卡片不可用

原实现让仪表盘与 B17 共用同一来源解析入口。若来源 resolver 违反内部契约并返回其他 tenant，
共用入口会把该不一致转换为 `ACCESS_DENIED`；仪表盘按设计捕获该错误并返回
`UNAVAILABLE`，因此映射或适配器故障可能被伪装成普通权限不足，而不是使整个请求失败。

处置：保留 B17 入口原有 `ACCESS_DENIED` 契约，仪表盘入口改为先解析来源、再以独立的内部
tenant 不变量校验失败关闭，最后执行展示范围收窄。只有已知的来源访问拒绝或字段不可用仍会
形成 `UNAVAILABLE`，内部 tenant 不一致抛出未知运行时失败并终止整个请求。

回归：`FixedReportQuerySupportTest` 同时验证仪表盘入口拒绝跨 tenant resolver 结果，以及 B17
入口继续返回稳定的 `ACCESS_DENIED`，避免修复改变既有公共报表错误语义。

### 2. B19b 趋势会静默合并重复周期并忽略范围外周期

原实现使用 `toMap` 的求和合并函数收集数据库趋势点，再仅遍历预期周期补零。若 mapper 或
SQL 返回重复周期，重复值会被静默相加；若返回请求范围外周期，该周期会被静默丢弃。两种情况
都会把持久化适配器契约故障伪装成正常统计结果。

处置：提取严格的趋势投影补齐器，先验证预期周期唯一且非空，再拒绝数据库返回的空值、重复
周期和非预期周期，最后只对真正缺失的周期补零并保持请求周期顺序。异常结果现在使整个请求
失败，不再产生看似有效的趋势。

回归：`MarketingFormSubmissionTrendProjectionTest` 覆盖稳定零桶、重复周期和范围外周期；
既有 B19b 集成测试继续覆盖 DAY/WEEK/MONTH、历史生命周期与真实 MySQL 聚合。

## 边界结论

| 边界 | 验收结果 |
| --- | --- |
| 身份与 tenant | 两个管理入口均从 `AuthenticatedCaller` 派生 tenant；来源访问、表单、台账和线索查询保持 tenant scoped，内部跨 tenant 结果失败关闭。 |
| B18b 权限收窄 | 每个来源独立解析真实能力和范围，再与保存的展示偏好取交集；偏好不能扩大权限，字段拒绝不泄露局部值。 |
| B18b 部分可用 | 仅已知访问拒绝或字段不可用产生 `UNAVAILABLE`；数据库、映射和未知运行时失败终止整个概览请求。 |
| B17 兼容性 | 共用来源查询仍保留 B17 的稳定访问拒绝语义，修复没有改变 B17 API 契约。 |
| B19b 原子性 | 线索与 append-only 成功台账在同一事务写入；任一失败整体回滚，失败或限流请求不产生成功事实。 |
| B19b 历史与当前可见性 | 趋势表示不随线索生命周期回写的历史成功量；链接分页在 SQL 内使用查询 caller 当前 `LeadVisibility`，隐藏记录不占页或 total。 |
| B19b 趋势映射 | 周期升序、缺失补零；重复、空值或范围外数据库周期作为适配器故障失败关闭。 |
| 数据最小化 | 台账只保存表单、版本、线索关系和数据库 UTC 时间，不保存匿名 payload、IP、请求头或线索字段。 |
