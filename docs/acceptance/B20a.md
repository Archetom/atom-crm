# B20a OA 字段与表单验收记录

验收日期：2026-07-19
验收结论：通过

## 验收范围

- 稳定的 `BusinessObjectType.OA_REQUEST` 与新、旧 tenant 内置字段 provision；
- tenant-scoped、版本化 `OaFormDefinition` 聚合和 MySQL 持久化；
- 管理端 CRUD、状态变更及普通成员可用目录/渲染接口；
- B05 当前字段元数据、角色字段访问、字段生命周期依赖；
- B11 OA 审批定义配置、发起范围及表单条件字段依赖；
- 跨 tenant 失败关闭、乐观锁、规范 code 唯一性和容量上限；
- 表单、字段和审批定义并发变化的数据库串行化。

## 契约结论

| 边界 | 验收结果 |
| --- | --- |
| 身份与 tenant | 所有用例从 `AuthenticatedCaller` 派生 tenant 并要求活动成员；表单、字段与审批仓储全部显式 tenant scoped。 |
| 字段目录 | 新 tenant 在组织初始化中幂等 provision；V52 为旧 tenant 回填 `request_title`、`form_code`、`applicant_actor`、`applicant_department`、`submitted_time`。 |
| 输入模型 | 表单只保存字段 code、顺序和必填标记；`request_title` 必填，服务端事实和 FILE 不能成为客户端输入。 |
| 当前策略 | 读取重建当前字段类型、选项、状态和访问；HIDDEN 字段不输出，可用目录要求每个输入字段当前具有 `WRITE`。 |
| 审批绑定 | 激活只接受同 tenant、`OA_REQUEST`、活动审批定义；条件字段必须是表单输入或服务端事实，发起范围在可用目录中重新校验。 |
| 生命周期 | 活动表单阻止引用字段停用、关闭 searchable 及审批定义停用或不兼容更新；表单停用和软删除保留故障关闭入口。 |
| 数据完整性 | V52 使用复合 tenant 外键约束创建者、审批定义和字段引用，生成列唯一键约束未删除表单的规范 code。 |
| 并发 | 相关写入共享 `(tenant, OA_REQUEST)` customization guard；表单在取得 guard 后才锁定并重建聚合，审批定义更新与状态切换也统一为 guard 优先、定义行锁随后。 |
| 上限 | 聚合限制 100 个唯一字段；guard 内计数保证并发创建不能突破每 tenant 200 个未删除表单。 |

## B11 阶段边界

B20a 只开放 `OA_REQUEST` 审批定义的字段目录、创建、更新、查询和状态管理，使表单可以安全绑定审批配置。审批预览、提交、实例查询和动作仍拒绝 `OA_REQUEST`；这些运行时能力必须由 B20b 的权威申请聚合、事实解析和参与者可见性共同交付，不能用客户端 `facts` 提前近似。

## 并发复核

聚焦 Testcontainers 用例先锁住 OA customization guard，再并发表单启用与审批定义停用。复核发现若表单在等待 guard 前先重建字段子项，MySQL `REPEATABLE_READ` 会保留旧审批快照，使两个互斥状态都可能成功。最终锁序调整为 OA 表单命令先取得 guard，再锁定并重建表单；回归结果固定为一个 HTTP 200、一个 HTTP 422。

同一用例在 199 个既有未删除表单上并发创建两个新表单，guard 内的容量检查只允许一个成功，最终数据库计数为 200。规范 code 的并发冲突继续由 tenant 唯一键最终仲裁。

审批定义更新与状态切换的回归先占住 OA guard，确认状态事务等待 guard 时仍可由独立连接取得定义行锁，再同时放行两条命令。两者按 guard、定义行的统一顺序串行执行，最终一个成功、另一个因旧版本返回 HTTP 409，不发生 definition row 与 object guard 的交叉等待。

## 已知非目标

- B20a 不创建 OA 申请记录，也不调用审批运行时；提交、幂等、申请快照和参与者可见性属于 B20b。
- 表单不支持 FILE；附件存储、扫描、下载授权和保留期需要独立文件批次。
- 已产生申请后的 code 不可修改规则要由 B20b 引入申请引用后执行；当前尚无申请历史可供依赖检查。
