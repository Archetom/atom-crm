# B29a 验收记录：Product / ReturnVisit 普通附件与结构化 FILE

## 实现范围

- `AttachmentTargetType` 新增 `PRODUCT`、`RETURN_VISIT`，并由两个显式 `AttachmentTargetAccess` adapter 注册；Product 叠加活跃成员、`files:read/write` 与 `products:read/write`，不引入数据范围；ReturnVisit 叠加 `files:read/write`、return-visit authority 与当前 READ/WRITE 可见范围。
- 普通附件继续走 target-first `/api/v1/attachment-targets/product/{id}/attachments` 与 `/api/v1/attachment-targets/return-visit/{id}/attachments`。目标锁、worker 锁和父删除都验证同 tenant 的 typed parent 且仅接受 ACTIVE 根。
- Product/ReturnVisit create 申请可选 `fileFieldDraftId`，create/update 申请 `fileFields`，响应返回可读、未掩码 FILE 的有序附件；每字段最多 10 个文件。FILE 不进入标量 `customFields`、产品快照、Activity 或工作台事实。
- 无 parent ID 的 FILE draft 在草稿创建、candidate intent、上传 admission、上传 finalize 和状态查询均重新验证当前业务写权限：Product 要求 `products:write`，ReturnVisit 要求当前 WRITE data scope；失权草稿不能继续占用存储或检查容量。直接目标草稿仍由对应 target adapter 验证当前目标权限。
- Product/ReturnVisit 软删除在父根锁内先关闭普通 relation 和 FILE binding，再保存删除状态。
- `V77__add_product_and_return_visit_file_targets.sql` 为普通 relation 和 FILE binding 添加 Product/ReturnVisit typed parent、同 tenant FK、exact-one CHECK、索引，并扩展 FILE draft object CHECK。
