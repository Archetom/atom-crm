# B27a 验收记录：Work 周期任务与受控 occurrence 生成

## 已交付

- `WorkTaskSeries` 以 DRAFT、ACTIVE、PAUSED、ENDED、DELETED 管理未来任务模板；人工接口为 `/api/v1/work/task-series` 及其 occurrence 分页子资源，继续使用 `work-tasks:read/write/manage`。
- 规则只接受 DAILY、WEEKLY、MONTHLY、受运行时目录支持的 IANA zone（拒绝 `+08:00` 等客户端 fixed offset）、一个 local time、有限 interval 与 month-day/LAST_DAY。DST gap 固定前移，overlap 固定 earlier offset；名义 local time、offset 和 resolved UTC 均进入 occurrence 与 generated task origin。
- `V67` 持久化 series、weekday/follower typed child rows、独立 occurrence facts、origin identity 和 generated-open unique slot；`V68` 为 tzdb/policy 升级增加 durable `RECONCILING` checkpoint。对账只接受属于当前规则的 nominal cursor，并在发布 `READY` 前将持久化 UTC due cursor 重写为该规则在目标 tzdb 下的 resolved UTC；不匹配的 nominal cursor 会回滚该批、保持目标 revision 未发布且不会生成任务。单一 series occurrence identity 与生成任务 origin identity 都由 MySQL 唯一键保护。
- B26 只新增 `WORK_TASK_RECURRENCE` fixed kind。run tenant、evaluation time、lease/fence 保持内部 exact context；effect 不构造 `AuthenticatedCaller`，并在同一事务内提交 cursor、ordinary WorkTask、occurrence 和 run success。series 读取返回持久化的 resolved-UTC `next_due_at`，不会按查询副本 tzdb 重新解释规则。
- 长停机 coalesce 到最新 due occurrence；已存在 TODO/IN_PROGRESS generated task 时记录 `SKIPPED/OPEN_TASK`，不堆积任务。编辑、暂停与删除仅影响 future generation；DRAFT/PAUSED 无 future 编辑不改变生命周期，无 future 激活明确失败。series `lastSafeReason` 与 occurrence `safeReason` 均透出为固定安全代码。`materialized`、`skipped` 与 `paused` 固定 outcome 指标仅在 effect 成功提交后递增；配置或 delay 非法仅关闭 recurrence kind，并以安全 fallback 保持进程可启动。
