# B25a 客户权限感知业务概览验收记录

## 交付范围

`GET /api/v1/customers/{customerId}/business-overview` 在一个只读 `REPEATABLE_READ` 快照中返回固定顺序的七张卡片：`CONTACT`、`OPEN_OPPORTUNITY`、`ACTIVE_CONTRACT`、`PENDING_INVOICE`、`ACTIVE_RECEIVABLE`、`ACTIVE_RECEIVABLE_PLAN` 和 `RETURN_VISIT`。卡片只包含来源、可用状态、数量以及适用时的金额；不返回关联记录名称、ID 或拒绝原因。

请求先在只读事务内通过 `CustomerAccessResolver` 与 Customer READ 可见性证明 exact Customer。隐藏、跨 tenant、`IN_POOL`、删除或其他不可见 Customer 在任何来源访问前安全失败。其后每张卡独立要求该来源的 `*:read`、READ 数据范围、direct `customer_id`、生命周期谓词，以及未隐藏且未脱敏的必需字段。只有已识别的 `ACCESS_DENIED` 会使单张卡退化为无数据的 `UNAVAILABLE`；未知异常仍会失败，不能伪装成权限不足。`UNAVAILABLE` 卡片的 `count` 和 `amount` 在 JSON 中省略，绝不以 `null` 暴露。

七个来源各自在所属 repository 内执行固定 tenant/customer/scope/lifecycle 聚合并返回类型化 summary 投影。没有通用跨域 repository、动态卡片、缓存或 Flyway 变更。现有 `(tenant_id, customer_id, status, ...)` 索引已由真实 MySQL `EXPLAIN` 覆盖。

Contact 下钻增加正数 `customerId`。列表先保留 Contact 自身的 `contacts:read`、数据范围、活动状态和公海排除，再证明同一 Customer 可见且 Contact `customer` 字段未遮罩；`customer_id` 条件在 SQL count/page 前加入，Customer 可见性不会扩大 Contact 范围。

## 关键证据

| Gate | 证据 |
| --- | --- |
| Customer-first 与事务边界 | `CustomerBusinessOverviewServiceImpl` 在调用任一来源 resolver/repository 前完成 Customer READ 可见性查询；该 access 在 `execute()` 内重新解析。`CustomerBusinessOverviewServiceImplTest` 覆盖根不可见时零来源调用，以及 access 仅在 `REPEATABLE_READ` 事务已开始后才解析。 |
| 固定卡片与来源隔离 | Service 显式按七来源稳定顺序编排，每张卡单独解析 authority、visibility 和 required fields；单元测试覆盖 Contact `ACCESS_DENIED` 只产生 `UNAVAILABLE`，其他卡继续可用。真实 MySQL 还证明协作者只扩展 Contact、Opportunity、Contract 三个本来支持协作者的来源，不能扩大 Invoice、Receivable、ReceivablePlan 或 ReturnVisit。 |
| 生命周期和金额 | `B25aIntegrationTest` 在真实 MySQL 写入 ACTIVE/OPEN、VOIDED/WON/ISSUED/DELETED/IN_POOL 对照记录，断言只有契约定义的直接客户记录进入数量和金额。 |
| 数据范围、字段策略与部分降级 | `B25aIntegrationTest` 用真实角色、成员和部门树逐一覆盖七个来源的 SELF、DEPARTMENT、DEPARTMENT_SUBTREE、TENANT 范围；它再逐一遮罩每张卡的必需字段，断言恰有对应卡降级为 `UNAVAILABLE`。Contact 的遮罩和隐藏回归同时断言 HTTP JSON 不含 `count:null` 或 `amount:null`。 |
| 空集与安全失败 | `B25aIntegrationTest` 断言可见空 Customer 的七卡均为 `AVAILABLE`/`0`，并覆盖 `IN_POOL`、删除和跨 tenant Customer 的安全 `404`。 |
| 同一快照 | `B25aIntegrationTest` 在 Customer 根查询已建立 `REPEATABLE_READ` 快照后暂停概览请求，提交一条 Contact 后才放行来源聚合；该请求仍返回 `0`，下一次新请求返回 `1`。 |
| 索引与 HTTP | `B25aIntegrationTest` 覆盖匿名 HTTP 拒绝、概览与 Contact drill-down 的 Customer/Contact 独立范围交集（任一域不可见即拒绝或空页），并对七张来源表执行 tenant/customer/status 的 `EXPLAIN`，断言 customer 路径索引是候选且计划不会全表扫描。 |
| 无 schema 扩张 | 新增代码只复用既有来源表、复合外键和 customer 路径索引；没有 Flyway migration。 |
