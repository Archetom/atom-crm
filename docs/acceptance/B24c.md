# B24c 受治理 FILE 字段验收记录

## 交付范围

B24c 使用独立的 draft、binding、OA value 与 B11/stage snapshot 关系保存有序 FILE 值；FILE 不进入标量 custom-field 或 approval facts。candidate 受 `files:write`、目标可协作性与当前 field `WRITE` 的交集控制；绑定、撤回、上传和 worker 都以 `target → draft → file` 的锁序执行。CRM whole-list replace 支持保留、重排和追加 candidate，历史 binding 不占用 active ordinal。

审批、stage 与 OA 输出和下载都重新应用当前业务可见性、`files:read`、field `READ` 与 mask。FILE 快照以内容版本和 evidence 保存；V63 增加独立 capture header，因此空快照也是不可变快照，V64 仅在父 approval/stage root 被清理时级联删除 header。V63 还允许未绑定 candidate 的 `WITHDRAWN` 子行保持空 evidence，撤回与过期清理不再触发 V62 的 CHECK 失败。

## 实际验证

- `FileFieldSnapshotOutputTest`：无 `files:read` 时审批/stage 响应不暴露文件计数、名称或大小。
- `FileFieldRepositoryImplTest`：首次空 approval/stage capture 只写一个 header，重试不会补写 child facts。
- `B24cFileFieldIntegrationTest`：真实 MySQL 中 `STAGED → WITHDRAWN` 未绑定子行保留空 evidence，并验证 V63 snapshot header 表。
