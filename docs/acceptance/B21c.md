# B21c acceptance

## Delivered boundary

B21c adds `WORK_TASK` as the ninth B15 worklist source without changing the Work-task aggregate, acknowledgement schema, CRM object catalog, or public task routes. A cursor-free query projects only tasks whose current assignee is the verified active member, whose status is `TODO` or `IN_PROGRESS`, and whose non-null due time falls on the requested date.

The source requires both `worklist:read` and `work-tasks:read`. Creator, follower, task-manager, and CRM relationship visibility do not substitute for current assignment. The repository applies tenant, assignee, active membership, status, date, and `(dueTime, taskId)` continuation before the SQL limit. Output uses `WORK_TASK` as both kind and subject type and points to the task ID; it never exposes or authorizes through the optional CRM relationship.

## Acknowledgement and projection version

The existing tenant/member acknowledgement model stores the exact `(WORK_TASK, taskId, worklistProjectionVersion, dueTime)` fingerprint. Exact or category acknowledgement only hides that projection and never changes task status. Title, priority, assignee, due time, and lifecycle changes advance the source version; description, follower, comment, and CRM-link changes do not. Completion, cancellation, deletion, reassignment, missing due time, or inactive assignment removes the source row through the next SQL query.

## Cursor compatibility

The emitted cursor version is `v3` with nine source positions. The decoder continues to accept date-bound `v2` cursors containing the former eight positions. It preserves those positions, initializes only the absent Work-task source as exhausted, and emits `v3` for any continuation. This prevents a newly deployed source from inserting an earlier task into a pagination chain that began before B21c; a cursor-free query starts all nine sources normally.

## Persistence and verification

No Flyway migration is required. The source reuses V53's `(tenant_id, current_assignee_actor_id, status, due_time, id)` index and the existing V45 acknowledgement table. Unit coverage verifies dedicated-source mapping, CRM-guard independence, per-source advancement, the active-assignee SQL predicate, projection-only root columns, fail-closed bounded category verification, and `v2` to `v3` compatibility. MySQL/HTTP integration coverage verifies all nine source kinds, the combined capability gate, current-assignee/open/due filtering, exact and category acknowledgement, unchanged task lifecycle, projection-version reappearance, reassignment disappearance, and legacy continuation behavior.
