# B28a 验收记录：OA 公告一次性定时发布

## 范围

B28a 为既有 OA 公告增加 `SCHEDULED` 状态、版本化的一次性排期和公告自有 publication occurrence。它不增加 B26 automation kind、通用 payload、cron/RRULE、外部通知、OA EMAIL 偏好或伪造的 `AuthenticatedCaller`；这些都仍属于后续 B28b 范围。

## 命令与生命周期

`POST /api/v1/oa/announcements/{id}/schedule` 只接受公告版本和显式 offset 的未来时刻。服务端将其规范化为 UTC，并仅在 publication lane 与统一 pulse 均可用时接受；时间必须至少晚于数据库 UTC 一分钟且不超过 365 天。创建或重新排期冻结公告内容和受众，递增 `publicationGeneration`，并创建唯一 `(tenant, announcement, generation)` occurrence。取消、重排、删除和立即发布都在 `organization_tenant -> oa_announcement -> occurrence` 锁序下结算旧 occurrence；`POST /{id}/cancel-schedule` 将根恢复为可编辑 `DRAFT`。

到期 pump 先在短事务中领取 exact occurrence，再在独立命令事务中重入上述锁序。它通过 tenant-scoped 授权投影复核原排期成员仍为活动成员且有 `oa-announcements:write`，不使用创建者、owner 或 worker 身份代替。共享 coordinator 随后重验冻结 selectors、解析至多 10,001 名当前活动同 tenant 成员，并在同一事务中写 `PUBLISHED` 根、最多 10,000 条不可变接收人快照和 occurrence 终态。过期、尝试耗尽、授权失效或确定性受众失败会把根恢复为 `DRAFT`，仅留固定管理安全原因；不暴露内部异常、成员或受众细节。

## 持久化与运行

V74 新增排期字段、`SCHEDULED` 生命周期约束、排期成员复合外键和 `oa_announcement_publication_occurrence`；V75 将 occurrence 的 `safe_reason` 与状态绑定，成功发布显式清空历史重试原因。occurrence 使用 database-UTC due/deadline、lease owner/fence、有限重试和有界终态保留；active-slot 唯一约束确保同一公告只能有一个活动 generation。默认 `atom.oa.announcements.publication.enabled=false`，关闭或配置非法只拒绝新的 schedule 命令，不影响草稿、立即发布、OA inbox 或已读回执。

## 验证

```bash
sh ./mvnw -q -pl application -am \
  -Dtest='OaAnnouncementTest,OaAnnouncementServiceImplTest' \
  -Dsurefire.failIfNoSpecifiedTests=false test

CI=true sh ./mvnw -q -pl start -am \
  -Dtest=OaAnnouncementIntegrationTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

集成测试经 HTTP 建立排期，验证唯一 durable occurrence 与提交后的 `scheduled` 指标；再以受控的 MySQL UTC 到期时刻调用真实 pump，验证公告发布、接收人快照和 occurrence 的 `PUBLISHED` 终态。它还覆盖双副本 claim、过期 lease takeover、stale fence 拒绝、重试后成功清空原因、重试耗尽与 misfire 的独立固定指标、排期成员授权撤销，以及重新排期与立即发布的并发竞争和所有 generation 结算。重新排期、立即发布、取消排期和删除仅在 occurrence 实际转为 `CANCELLED` 且事务提交后递增 `cancelled`；worker 失去 lease 不伪造取消结果。
