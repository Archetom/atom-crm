# B30a acceptance: permission-aware bounded Customer CSV export

## Implemented scope

- `POST /api/v1/customers/export/csv` requires `customers:export` at the security route and independently resolves both `customers:export` owner scope and `customers:read` visibility in the application query transaction.
- `CustomerExportQuery` preserves those two predicates separately. The Customer repository applies both in SQL while retaining active, non-pool Customers, validated keyword/name/owner/starred/saved-view filters, and `customer_id ASC` ordering.
- The export accepts 1–50 ordered unique field codes and rejects unknown, inactive, hidden, masked, duplicate, relation, collection, FILE, or other unsupported fields. Only the fixed scalar catalog is projected.
- The service probes at most 5,001 IDs, reads output in 200-ID batches, builds one UTF-8 BOM CSV inside a read-only `REPEATABLE_READ` transaction, and rejects documents exceeding 16 MiB before HTTP output begins.
- The returned one-shot `CustomerCsvDocument` owns the shared Customer/Contact/Lead local non-queueing admission lease (one per member, four per replica) until write completion, failure, or cancellation. REST only writes the completed document with `no-store`, `nosniff`, and the fixed `customers.csv` disposition.
- RFC 4180 encoding uses CRLF, stable field-code headers, typed scalar normalization, and formula hardening before quoting. The feature creates no B24 file, storage object, job, receipt, history, or download token.
