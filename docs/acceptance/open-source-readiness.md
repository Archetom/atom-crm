# 前后端开源准备检查记录

检查日期：2026-10-27。范围是当前 `atom-crm` 与 `atom-crm-web` 的安装、生产装配、构建交付、依赖风险、协作入口及公开仓库准备，不是一次完整的业务安全审计。

源码公开于 [Archetom/atom-crm](https://github.com/Archetom/atom-crm) 和 [Archetom/atom-crm-web](https://github.com/Archetom/atom-crm-web)。开源准备检查完成后，按维护者要求分别创建了新的初始提交，旧 Git 元数据只在本地备份，不进入公开历史。本次没有发布版本制品或部署生产。

## 已发现并修复

| 缺项或问题 | 补齐结果 |
| --- | --- |
| 前后端入口脱节，快速开始沿用开发身份头，清理示例说明会误删登录依赖 | 更新中英文 README、双仓库启动、`/setup`、密码登录与生产边界；移除把 `clean-sample` 当作正常安装步骤的引导 |
| 缺少开源协作与漏洞报告流程 | 两仓库增加 CONTRIBUTING、SECURITY、Issue/PR 模板和计划仓库链接；保留已有 MIT，前端补齐 package 许可证元数据，后端增加 CHANGELOG |
| 后端 `prod` 缺少欢迎通知实现而无法启动 | 增加显式配置的 SMTP 适配器；无配置仍失败关闭，开发环境继续使用不投递的日志适配器 |
| 配置了 SMTP 后，密码重置发送器仍可能因条件检查顺序而不注册 | 移除过早的 bean 条件；由显式开关和构造注入确保发送器可用，增加装配回归 |
| `conf/**` 全量打包可能带入本地覆盖文件 | 改为运行资源白名单；测试配置只进入测试 classpath；补充环境与私钥文件忽略规则 |
| 缺少后端运行镜像和完整生产变量模板 | 增加非 root Dockerfile、`.dockerignore`、`.env.example` 和[部署指南](../deployment.md)；镜像只复制验证后的可执行 JAR |
| 发布脚本可能接受数据库测试全跳过的构建 | 增加 Docker 前置检查和实际 Surefire XML 门禁，覆盖每个当前数据库测试类；兼容显示名称、参数化、动态及嵌套测试 |
| CI 缺少固定引用、报告留存与依赖更新入口 | 两仓库固定 Action 完整 SHA、禁止 checkout 持久凭据、保留报告并配置 Dependabot；后端 CI 另构建运行镜像 |
| 前端锁定 Zod 4.4.3 命中高危公告 | 最小升级并锁定到 4.6.6，生产依赖审计恢复通过；见 [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) |
| 前端容器联调监听地址和文档端口不一致 | 容器内显式监听 `0.0.0.0`，宿主仍限制回环；seed 和 Vite 代理统一到 Compose 的 18080 端口 |
| 浏览器验收使用旧开发身份入口，冷缓存首屏还会出现 Vite 504 | 测试改用真实 `/dev/session`；显式预扫描客户端路由依赖，冷缓存、新服务器下验证通过；未增加重试或放宽错误断言 |
| 生产关闭的 API 文档地址被兜底异常处理映射为 500 | 框架资源/路由不存在时返回已有 RESOURCE_NOT_FOUND 的安全 404，不回显路径、请求头或异常消息 |

欢迎邮件沿用现有提交后异步事件，不承诺持久重试。它不会启用独立的工作通知 EMAIL 通道，也不会绕过文件、电话、企业数据或后台调度的 readiness 条件。

## 实际验证

后端使用 JDK 25.0.3、Maven Wrapper 3.9.16 和 Docker/MySQL 9.7.1：

| 检查 | 结果 |
| --- | --- |
| SMTP 发送及装配聚焦回归 | 8 个测试通过；包含缺失配置失败、开发环境不真实投递、密码重置 bean 注册和发送失败传播 |
| `make release-verify` | 1,392 个测试通过，0 失败、0 错误、0 跳过；50 个数据库测试类共实际执行 422 个用例 |
| 数据库报告验证器自测 | 20 项正反例通过，包括无报告、跳过、失败、显示名称、嵌套报告和恶意/损坏 XML |
| 打包隔离 | 临时加入无敏感内容的 `*-local.yml` 哨兵后，发布 JAR 无该文件、无 `application-test.yml`；测试 classpath 保留测试配置；哨兵已删除 |
| 后续 404 修复回归 | `sh ./mvnw -pl infra/rest -am test -Datom.test.skip-database-tests=true`：716 个测试通过，0 失败、0 跳过；包含真实异常处理器选择及响应/日志不泄露敏感路径的断言 |
| 最终构件 | 404 回归后执行 `sh ./mvnw install -DskipTests` 重建并同步本地构件；此命令只用于打包，不作为新增测试证据 |
| 最终 Docker 镜像烟测 | 以 `10001:10001` 运行；隔离 MySQL 下 prod/dev 健康检查均为 UP，首次安装状态正确，匿名请求及伪造开发身份头均返回 401，关闭的 API 文档返回 404；临时容器和网络已清理 |

全量发布门禁先于最后的 404 修复执行；该小范围 HTTP 映射随后由 REST 及依赖模块回归和最终镜像烟测验证，没有再次重复全量数据库测试。镜像烟测配置了 SMTP bean，但关闭外部邮件健康探针且未发送邮件，不能作为实际 SMTP 网络或投递成功的证据。

## 敏感信息检查范围

扫描当前后端跟踪文件及两个仓库全部可达 Git 历史的 blob：后端 7,452 个、前端 6,131 个。私钥块、GitHub token、AWS access key、Slack token、Google API key、Stripe live secret 六类常见格式均无命中。另清理了当前历史审查文档中的四处机器绝对路径。

这是有界的格式扫描，不能识别所有任意格式密码、个人数据或内部资料，也不包含远程未获取的 refs、外部制品和托管平台设置。上述扫描针对重新初始化之前的本地历史；公开仓库由新的独立根提交建立，旧 Git 元数据仅保留在本地备份。
