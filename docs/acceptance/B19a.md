# B19a 营销表单复审验收记录

验收日期：2026-07-18
验收结论：通过（复审发现的安全与并发问题已修正并回归）

## 验收范围

- 管理端 `marketing-forms:read/write`、活动成员与 tenant 隔离；
- 公开标识、匿名渲染、提交白名单与最小响应；
- B05 LEAD 字段目录、字段权限、必填字段和活动依赖；
- B09 负责人能力、数据范围、线索创建与 6907 错误场景；
- 表单更新、停用、字段生命周期和在途提交的锁顺序；
- 公开路径规范化、受信来源解析和有界本地限流；
- 事务原子性、数据库连接占用和并发失败关闭。

## 复审发现与处置

### 1. 持锁嵌套事务可能耗尽连接池

原实现先在 B19a 外层事务取得表单根记录锁，再调用使用 `REQUIRES_NEW` 的 B09
`LeadCommandService.create`。并发提交达到连接池上限时，每个请求都可能持有外层连接并
等待第二条内层连接，形成连接池饥饿；内层成功后若外层提交失败，也无法原子回滚线索。

处置：提取 `LeadCreationCoordinator` 作为 B09 创建操作的组合入口。公开提交在持有表单锁的
同一事务中执行该操作；普通 B09 创建仍通过 `CommandServiceTemplate` 独立运行。预期业务失败、
悲观锁失败和安全包装后的内部失败继续使用 `MARKETING_FORM_SUBMIT`（6907）场景。

回归：`MarketingFormSingleConnectionIntegrationTest` 将 Hikari 最大连接数设为 1，完成表单
创建、激活和匿名线索提交，证明该路径不再申请嵌套连接。

### 2. 未知公开顶层属性被静默忽略

测试环境显式配置 Jackson 忽略未知属性，因此匿名请求可携带 `tenantId`、`ownerActorId` 或
`status` 等无效顶层字段而不被拒绝。虽然这些值未参与授权或持久化，但行为不符合严格公开
白名单和失败关闭契约。

处置：`MarketingFormSubmissionRequest` 使用 `@JsonAnySetter` 拒绝所有未知顶层属性；字段
映射仍只接受锁定表单中已配置的精确 `fieldCode`。

回归：`MarketingFormIntegrationTest.publicSubmissionRejectsUnknownIdentityAndLifecycleProperties`
验证注入请求返回 HTTP 400 且不会创建线索。

## 边界结论

| 边界 | 验收结果 |
| --- | --- |
| 身份与 tenant | 管理端 tenant 只来自 `AuthenticatedCaller`；公开 tenant 与负责人只来自规范 public ID 定位的持久化表单。 |
| 负责人授权 | 激活、渲染和提交均通过 B09 `LeadAccessResolver` 解析当前有效成员、`leads:write` 与真实数据范围。 |
| 字段安全 | 仅公开安全字段可配置；负责人必须拥有 `WRITE`；当前必填字段必须公开为必填；活动依赖阻止字段停用。 |
| 匿名输入/输出 | 未知顶层属性、未配置字段和不合类型值失败关闭；成功响应不含 tenant、负责人、线索 ID 或版本。 |
| 并发顺序 | 提交、更新、状态变更和删除先锁表单根，再进入 LEAD 自定义对象锁；在途提交与配置变化形成数据库顺序。 |
| 事务与连接 | 表单锁和 B09 创建共享一个事务与连接；失败统一回滚，不存在持锁等待第二连接的池饥饿。 |
| 限流 | direct/alias/等价编码路径共享规范表单桶；表单与受信来源配额原子消费；桶有界、过期且容量满时失败关闭。 |
| 错误场景 | B09 参数、领域唯一性、并发与内部失败均在公开边界归入 6907，内部堆栈不进入响应。 |

## 已知非目标

- 内置限流是单副本内存态；多副本全局配额仍由网关或共享限流服务负责。
- 匿名提交不是幂等接口；重复的有效请求可能创建多条线索。若产品需要网络重试去重，应在后续批次引入有界幂等键，而不是依赖本地限流。
- public ID 是不可预测的定位句柄而非认证凭据；授权事实始终来自持久化负责人及其当前策略。
