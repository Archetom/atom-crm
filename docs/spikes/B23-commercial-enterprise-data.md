# B23-C 中国商业企业数据模型只读 spike

> 调研日期：2026-07-19
>
> 公开契约漂移复核：2026-07-20
>
> 代表模型：企查查开放平台企业模糊搜索（ApiCode 886）、企业工商信息（ApiCode 410）、企业工商详情（ApiCode 735）
>
> 证据范围：只读取供应商公开页面、公开帮助中心和公开用户服务协议；未注册账号、未申请接口、未调用数据 API、未接触真实响应、凭证、付费文档或商务合同
>
> 状态：B23-C 只读调研完成；后续 B23-XI/B23-XP 已闭合 identity、profile 与 policy oracle，B23-XF 已执行商业 native shape 的合成查询 fixture；这些结果不表示选择企查查、取得数据许可或满足生产 adapter readiness

## 1. 结论

企查查公开模型证明 B23 的 provider-neutral 边界有必要，也暴露了首期不能直接照搬供应商 DTO 的原因：

- 886 是宽泛关键词搜索，不是“企业名称专用搜索”。公开说明允许企业名、人名、产品名、地址、电话和经营范围，返回中还直接包含法定代表人姓名；B23 只能在私有 adapter 中把它收窄为非空企业名称、第一页和最多 5 个候选。
- 410 已足以提供首期大部分基础登记事实，但同名字段会随主体性质改变语义，`CreditCode` 对大陆企业表示统一社会信用代码、对中国香港企业表示商业登记号码；没有 `EntType` 与明确 scheme 校验就不能生成规范登记身份。
- 735 把基础工商信息与股东、主要人员、联系方式、年报联系方式、分支机构、变更记录和企业画像放在同一大响应中。首期若仅需基础 profile，不应把这个响应或其中任意扩展 map 提升为公共模型。
- 公开接口页没有给出完整登记状态枚举、观测有效期、source revision、稳定 attribution 文案、缓存/持久化许可或数值化并发上限。供应商 `UpdatedDate` 也不是本次请求的 `observedAt`。
- 公开用户服务协议提供的是受账号、申报场景和服务规则约束的合同使用边界，不是开放数据许可证；它限制转让、第三方数据服务、不合理批量获取和数据出境，并允许接口、字段、频次与计费规则变化。
- 2026-07-20 复核时，886/410/735 的查询、字段、认证、价格和候选/集合上限仍与初始记录一致；但用户服务协议页面已经显示 `2026-07-19` 的更新/生效日期且正文仅呈现“无数据”，原请求状态码 URL 也重定向到另一个站点。旧协议条款和旧状态码目录只能作为带日期的 spike 输入，不能继续充当生产配置的当前证据。

因此 B23-C 可以冻结一个“商业供应商形态”的合成 fixture，但真实 adapter 默认只能是 `NOT_READY`。只有部署方合同明确允许当前 tenant 的展示、择取、持久化、attribution、保留、删除和地域范围，并由私有 adapter fixture 证明状态、身份、字段、额度与错误映射后，才可开放相应操作。

## 2. 公开证据与判读边界

本 spike 只使用下列公开资料：

- [企业模糊搜索 886](https://openapi.qcc.com/dataApi/886)：查询参数、最多 5 条候选、候选字段、公开试用与次数套餐。
- [企业工商信息 410](https://openapi.qcc.com/dataApi/410)：按统一社会信用代码或企业名称查询、主体性质和基础照面字段、公开试用与次数套餐。
- [企业工商详情 735](https://openapi.qcc.com/dataApi/735)：基础信息、股东、主要人员、分支、变更、联系信息、年报联系信息及各集合的公开上限。
- [接口服务模式](https://openapi.qcc.com/services/pre/api)：按次数、余额和企业户三种计费模式及两年有效期/年度企业清单语义。
- [常见问题](https://openapi.qcc.com/services/after/faq)：IP 白名单、签名时间戳 5 分钟有效、有效请求计费和额度提醒。
- [请求状态码](https://openapi.qcc.com/services/after/status)：2026-07-19 初始读取到认证、权限、余额、日限额、并发、维护、参数、无结果和系统错误分类；2026-07-20 复核时该 URL 重定向到 QCC 国际站首页，已经不能作为当前状态目录。
- [企查查开放平台用户服务协议](https://openapi.qcc.com/services/protocol/tos)：2026-07-19 初始读取到的最新可选详细版本为 `2025-07-31`；2026-07-20 复核时页面改为显示更新/生效日期 `2026-07-19`，但公开正文仅呈现“无数据”，无法比较新旧条款。真实部署必须取得并审查实际生效的完整协议、商务合同和服务规则。
- [GB 32100-2015 国家标准页](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=24691C25985C1073D3A7C85629378AC0&refer=outter)：统一社会信用代码必须作为明确 scheme 校验，不能当任意供应商字符串。

公开页面中的字段说明和示例只能证明文档化的响应形态，不能证明实际覆盖率、数据准确率、所有枚举值、更新 SLA 或某个真实主体的当前事实。本文不以供应商营销描述替代许可、时效或法律结论，也不推断未公开的接口能力。

## 3. 查询模型映射

### 3.1 有界名称搜索

| 供应商公开契约 | B23-C 处理 | 原因 |
| --- | --- | --- |
| 886 `searchKey` 支持企业名、人名、产品名、地址、电话、经营范围等 | 公共请求只接受裁剪后的企业名称；禁止人员、电话、地址、产品和经营范围搜索模式 | 防止 B23 变成人员发现、联系方式补全或任意供应商搜索代理 |
| 可提交 `pageIndex` | adapter 固定请求第一页；公共请求不透传 page、offset 或排序 | 首期不提供批量遍历 |
| 每次最多返回 5 条，响应含供应商总数 | capability 的候选上限固定为 5；公共响应不承诺或返回供应商总数 | 上限取供应商与核心政策的更小值，不能用总数构造翻页器 |
| 候选含 `KeyNo`、`Name`、`CreditCode`、`StartDate`、`OperName`、`Status`、`No`、`Address` | 仅白名单化主体字段；`OperName` 在 adapter 内丢弃，`KeyNo` 只能作为私有短期 locator 候选 | 人员字段不进入首期；供应商主键不是登记身份 |

886 返回的 `CreditCode` 语义可能是大陆统一社会信用代码，也可能是中国香港商业登记号码，而该候选形态没有公开的 `EntType` 字段。因此候选列表本身不能证明 `(jurisdiction, registryScheme, registryValue)`。

B23-C 只允许满足 GB 32100 形态与校验规则的 18 位统一社会信用代码候选进入“可选择”路径。选择后必须用该 code 调用 410 重新取得详情，并以详情的主体性质和 code 一致性再次验证；无法形成明确 scheme 的候选可以安全展示为不可择取项，也可以直接过滤，但不能退化为用 `KeyNo`、名称或地址建立长期关联。

公开文档没有说明 886 的 `KeyNo` 可作为 410 的查询参数。adapter 不能假定未文档化的候选到详情跳转能力，也不能把名称二次查询的第一条结果当作原候选。

### 3.2 精确登记身份查询与详情

410 的 `keyword` 公开支持统一社会信用代码和企业名称；对社会组织和中国香港企业，文档只承诺企业名称查询。B23-C 首个可证明的精确 profile 因此收窄为：

```text
jurisdiction = CN_MAINLAND
registryScheme = CN_USCC
selector = a locally validated USCC
subject gate = EntType 0 (mainland enterprise)
detail = 410 result whose CreditCode confirms the same scheme/value
```

本 spike 不从 410 的自由文本企业名称查询推导唯一身份，不把中国香港商业登记号码、中国台湾企业编号、社会组织或其他主体混入 `CN_USCC`。后续若支持其他主体，必须分别定义 jurisdiction/scheme、查询限制和 fixture。

735 的 `searchKey` 还公开支持供应商 `QccCode`，但 `QccCode` 与 `KeyNo` 都是供应商身份。它们可以留在私有 adapter 的短期相关性范围内，不能成为 Customer ID、tenant 绑定、登记 scheme 或跨供应商主键。

### 3.3 手工刷新

公开 API 没有独立“刷新”语义。B23 手工刷新只是对已保存的 `(CN_MAINLAND, CN_USCC, value)` 再次执行 410 精确查询并生成新观测：

- 不发送 Customer 当前名称、地址或状态作为权威 selector；
- 不因新查询无结果就删除关联或改写本地 Customer；
- 不把 410 的 `UpdatedDate` 当成本次 `observedAt`；
- 不在持有 Customer 或 customization 锁时等待外部调用。

## 4. 基础字段、人员字段与丢弃规则

### 4.1 首期 allowlist

| 供应商字段 | 规范语义 | B23-C 决策 |
| --- | --- | --- |
| `EntType` | 主体性质判别 | 只作 adapter gate；不把供应商枚举暴露到核心 |
| `CreditCode` | 可能的登记标识 | 只有与主体性质一致且通过 `CN_USCC` 校验时成为 registry value |
| `Name` | 登记名称 | 可映射为候选/详情的登记名称；择取仍经过 B05/B06 字段写权限 |
| `Status` | 供应商登记状态文本 | 公开文档没有完整枚举；只有经私有 fixture 审定的值可映射，其余一律 `UNKNOWN` |
| `EconKind` | 企业类型文本 | 可作为有界、可选的组织类型展示候选；不能当公共枚举或授权事实 |
| `StartDate` | 成立日期 | 格式和范围校验成功后可映射为可选成立日期 |
| `Address` | 注册地址 | 可映射为单一登记地址观测；不宣称营业/邮寄/唯一主地址 |
| adapter receive time | 本次取得事实的时间 | 由 adapter 在成功解析后生成 `observedAt`，不从供应商业务字段取得 |
| contract/policy TTL | 观测到期时间 | 只能由已审查的部署政策产生；公开页面未给 TTL，缺失时不能宣称可持久化择取 |

### 4.2 不进入公共 profile 的字段

下列公开字段即使存在也不在 B23 首期 allowlist：

- 供应商身份与资源：`KeyNo`、`QccCode`、Logo URL、网站 URL、订单号和任意资源链接；
- 人员与关系：`OperId`、`OperName`、`DesignatedRepresentativeList`、`Partners`、`Employees`、股东标签、最终受益股份、关联产品/机构和分支机构法定代表人；
- 联系方式：`ContactInfo.PhoneNumber`、`ContactInfo.Email`、网站列表，以及 `ARContactList` 中的电话、邮箱和通讯地址；
- 扩展企业画像：`TagList`、新兴行业、股票、融资、风险、司法、知识产权及 735 中任何未列入 allowlist 的子对象；
- 大段或历史内容：经营范围、变更前后内容、注销/吊销原因、曾用名列表和原始 profile；
- 未纳入首期 scheme 的备用标识：工商注册号、组织机构代码、地区代码及随主体性质改变语义的编号。

这不是对上述字段是否“公开”的判断，而是 B23 首期用途、隐私和许可最小化。私有 adapter 必须从供应商 DTO 构造一个新的固定规范对象；不能先把完整 735 对象、原始 JSON 或动态 map 交给核心后再依赖 UI 隐藏。

### 4.3 人员数据验证结论

公开文档证明人员数据不只存在于专门的人员接口：

- 886 候选直接返回法定代表人姓名，并允许用人名作为搜索词；
- 410 基础照面含法定代表人 ID/名称和委派代表；
- 735 含最多 100 条股东和最多 100 条主要人员，并混有股东、受益、分支人员、电话和邮箱等关系或联系字段；
- 独立的[企业人员董监高信息 669](https://openapi.qcc.com/dataApi/669)还把人员姓名、人员主键、任职、对外投资、法定代表关系和企业风险计数组合在一起。

因此“只调用工商接口”不等于“不会取得人员数据”。首期 adapter 的响应白名单、日志检查和 fixture 必须覆盖嵌套人员字段；人员姓名、人员主键、职位、股东、受益关系、电话与邮箱在返回核心前丢弃，不能进入搜索历史、缓存、provenance、Activity、事件或可观测性。

## 5. 状态、观测与 provenance

### 5.1 登记状态

410/735 只把 `Status` 描述为登记状态，886 的公开示例出现一个状态文本，但公开文档没有完整、版本化枚举，也没有说明新增值策略。B23-C 因此不冻结供应商文本到 `ACTIVE`/`INACTIVE` 的生产表：

- 私有 adapter 可以在合同文档与真实合成 fixture 复审后维护明确 allowlist；
- 任意未识别、空白、冲突或新增值映射为 `UNKNOWN`；
- 不能依据注销原因、企业画像、风险分或其他旁路字段推断登记状态；
- `UNKNOWN` 仍可用于人工展示，但不能伪装成 active、认证通过或风险可接受。

缺少完整状态枚举是生产 adapter readiness 的阻断项，不影响用合成原始枚举证明 `UNKNOWN` 失败关闭。

### 5.2 时间与版本

公开模型提供成立日、核准日和 `UpdatedDate` 等业务/来源更新字段，但没有提供：

- 本次响应在供应商侧形成的可信观测时间；
- 不可变 source revision 或响应版本；
- ETag、digest 或可供重新取得同一历史观测的标识；
- 数据 TTL、缓存期限或择取有效窗口。

因此：

- `observedAt` 是 adapter 成功接收并白名单化当前响应的本地时间；
- `UpdatedDate` 不替代 `observedAt`，也不伪装成 source revision；
- `expiresAt` 只能来自合同和部署政策，不能由字段缺省值猜测；
- 客户端回传的任何名称、地址、状态、日期、`KeyNo` 或更新时间都不可信，择取前按 USCC 重新查询。

### 5.3 最小 provenance

公开资料目前只能支持以下候选：来源类别、规范登记身份、adapter 生成的 `observedAt`、策略版本、操作者和实际采用的 B05 field code 集合。是否保存供应商显示名、链接、revision、digest、订单号或短期 locator，必须由商务合同与 attribution/保留政策决定。

在该政策未闭合时，B23-C capability 最多声明 `EPHEMERAL_ONLY`，不能声明允许持久化择取。搜索候选、原始 profile、735 子集合、未采用字段和供应商订单号始终不进入开源 MySQL。

## 6. 许可、attribution、保留与地域

2026-07-19 初始读取的最新详细公开用户服务协议版本为 `2025-07-31`。2026-07-20 复核时，公开页面已标注更新/生效日期 `2026-07-19`，但没有呈现可审查的协议正文。所以下列内容只记录旧版公开文本暴露过的风险边界，不代表对当前条款的确认：

- 服务与数据使用受账号、已填写的使用场景、具体页面规则以及可能存在的纸质合同共同约束；纸质合同冲突时以纸质合同为准。
- 账号、所购服务和密钥只限账号主体使用，不得赠与、借用、转让或售卖。
- 协议限制把取得的数据用于第三方数据服务、相同/类似产品，以及未经书面授权的抓取、复制、公开展示、传输或提供第三方使用。
- 不允许恶意、非法、连续频繁或不合理的大批量获取、复制和镜像；平台可以据此限流、停用账号或封禁 IP。
- 公开条款要求取得的信息只在中国大陆存储和使用，不得向境外提供或允许境外主体查询、下载、导出。
- 如法律要求，用户需事先取得信息主体授权；数据已公开或接口可购买不自动消除该责任。
- 供应商不把返回内容承诺为准确、真实、完整或及时的确认，并保留因数据来源、产品迭代或经营规则调整接口、字段、频次和计费的权利。

这些历史公开条款没有形成适用于本仓库的开放数据许可证。当前协议正文不可读也不能反向证明限制已经取消。公开 API 页面和两次协议读取均没有给出 B23 UI 可直接采用的固定 attribution 文案、logo 规则、来源链接格式、缓存期限、Customer 持久化期限、终止后的数据处置或再导出授权。

所以不能从“公开页面未写必须署名”推导“无需 attribution”，也不能从“API 面向 CRM/ERP 对接”推导可永久复制、跨 tenant 缓存或随 Customer 导出。每个真实 connector 的部署政策必须绑定已审查合同版本并明确：

1. 允许的 tenant、用户群、业务场景和主体范围；
2. 搜索候选展示、详情展示、逐字段择取、持久化、缓存、审计和导出是否分别允许；
3. attribution 的准确文案、商标/链接规则、展示位置与不可用时行为；
4. 观测 TTL、缓存/审计上限、合同终止、纠错、异议与删除处置；
5. 中国大陆存储/访问、人员字段和分包处理要求；
6. 账号、套餐、并发、调用量和费用归属。

任一必需项缺失时，对应 capability 为 `NOT_READY` 或 `EPHEMERAL_ONLY`；核心不能用默认文案或“来源：互联网”补齐。

## 7. 额度、计费与调用边界

### 7.1 公开额度事实

截至调研日，公开页面展示：

| 接口 | 单次公开价格 | 免费试用 | 公开次数套餐示例 | 响应上限 |
| --- | --- | --- | --- | --- |
| 886 模糊搜索 | 0.10 元/次 | 20 次 | 10,000 / 50,000 次 | 每次最多 5 个候选 |
| 410 工商信息 | 0.20 元/次 | 20 次 | 5,000 / 25,000 次 | 单主体基础详情 |
| 735 工商详情 | 2.00 元/次 | 20 次 | 500 / 2,500 次 | 股东、人员、分支、变更各前 100 条 |

价格和套餐是带日期的公开页面观测，不是 B23 公共契约。公开服务模式还说明：

- 次数与余额通常两年有效，调用时先扣已购次数再扣余额；
- 企业户按固定企业清单形成通常一年的计费周期，周期内同一企业不限调用量，但成功占用企业名额且没有公开的清单重置容错；
- FAQ 表示所有“有效请求”正常计费，因此无结果或供应商认可的参数错误也不能默认视为免费重试。

### 7.2 未公开的额度事实

公开状态码区分每日系统限制、服务期总量限制、并发限制、系统流量异常和余额/次数不足，但本次公开资料没有给出 886/410/735 的统一数值化 QPS、并发值、每日上限、`Retry-After` 或 HTTP 429 保证。

因此 capability 只能暴露核心需要的安全事实，例如“当前可尝试”“候选上限 5”“额度不可用”，不能暴露套餐名、余额、价格或臆造数值 QPS。私有 adapter 必须使用合同配置的 deadline、并发门、调用预算和熔断；缺少数值政策时不得靠不断试错探测上限。

名称搜索和精确详情是计费的独立调用。预览或择取为取得新鲜观测而重新查询会再次消耗额度，UI 和实现不能暗示一次搜索永久覆盖后续刷新。普通 B06 API 不依赖这些额度。

## 8. 认证与安全错误映射

### 8.1 私有认证边界

886/410/735 的公开请求模型均使用 HTTPS GET：

- query 中包含应用 `key` 和搜索词；
- headers 包含 `Token` 与秒级 `Timespan`；
- `Token` 按公开规则由 `key + Timespan + SecretKey` 计算 MD5 大写值；
- FAQ 表示时间戳按北京时间校验且有效期为 5 分钟；
- 账号安全页可配置 IP 白名单。

这只是供应商传输认证，不是 B23 的 caller、tenant 或 connector 身份。真实实现必须把 key、SecretKey、Token、Timespan、供应商账号和 IP 策略留在私有 adapter/secret 管理中；普通请求不能选择或覆盖它们。

由于 key 与企业查询词位于 URL query，私有 HTTP client、代理、APM、异常和 access log 必须关闭完整 URL/query 记录。完整企业名、USCC、地址、Token、供应商错误、订单号和响应 body 都不能进入核心日志、trace、metric、事件或 Activity。

### 8.2 provider-neutral 收敛

下表依据 2026-07-19 可见的公开状态目录形成 spike 级安全分类，不预占最终 Java 枚举或公共错误码。由于该目录在 2026-07-20 复核时已经不可从原 URL 取得，它只可继续驱动合成 fixture；真实 adapter 必须用当前合同目录和私有 conformance 重新证明映射：

| 供应商公开状态 | adapter 安全分类 | 普通 B23 行为 |
| --- | --- | --- |
| `200` | `SUCCESS` | 继续严格解析 allowlist；结构错误仍失败关闭 |
| `201` | `NO_RESULT` | 返回无结果，不使用缓存旧值伪装成功 |
| `202/125/126/213/215/223/224` | `QUERY_REJECTED` | 公共输入应先本地校验；外部仍拒绝时只返回安全的不支持/无效查询，不透传字段或原文 |
| `207/209` | `QUERY_TOO_BROAD` | 不自动翻页或缩放为批量扫描；要求用户收窄或返回不支持 |
| `208/218/219` | `UNSUPPORTED_SUBJECT_OR_OPERATION` | 稳定返回不支持，不推断主体不存在 |
| `102/109/112/116` | `QUOTA_UNAVAILABLE` | 不重试；仅 B23 不可用，普通 Customer API 正常 |
| `120/122` | `CAPACITY_LIMITED` | 有界退避或熔断；禁止并发放大和无限重试 |
| `101/103/104/106/107/108/111/113/114/115/118/119/121/123/214` | `BINDING_OR_POLICY_UNAVAILABLE` | 普通用户只看到来源不可用；账号、签名、IP、权限、地域、购买/认证原因仅进入受限运维审计 |
| `105/110/124` | `SOURCE_NOT_READY` | 下线、相同查询冷却或维护均打开 readiness/circuit；不抓网页兜底 |
| `199/203` | `SOURCE_FAILURE` | 安全不可用，可按只读调用政策有限重试；不透传供应商消息 |
| `205` | `PENDING_UNSUPPORTED` | 这三个首期同步用例没有公开异步完成契约；不得把 pending 当成功或自行轮询未知接口 |
| 未知状态、超时、非预期 HTTP、畸形/超限响应 | `SOURCE_FAILURE` | 失败关闭、无 Customer 写入、无原始错误泄露 |

普通调用者不需要知道 key 是欠费、暂停、签名错误、IP 禁止、跨境阻断还是接口未购买。tenant 数据管理员可以读取 provider-neutral 的“绑定/政策不可用、额度不可用、维护中”一类有界原因；账号、余额、套餐、IP、签名、订单号和供应商状态原文只属于私有运维边界。

供应商状态码是响应 body 的应用状态。公开资料没有承诺每类状态对应哪个 HTTP status，也没有 `Retry-After` 契约；adapter 不能只看 HTTP 2xx 就判成功，亦不能把未知 HTTP 429/5xx 的响应原文提升为公共错误。

当前公开状态目录不可取得时，不允许从旧表推断未知或复用 code 的新语义。未被当前私有 fixture 证明的响应统一收敛为 `SOURCE_FAILURE` 或使 binding `NOT_READY`。

## 9. B23-C 合成契约 fixture

商业模型 fixture 不保存供应商样例或真实主体，只构造确定性的虚拟值，并至少证明：

1. 886 只接受企业名称模式、固定第一页和最多 5 个候选；人员名、电话、地址、产品、经营范围和任意透传过滤失败关闭。
2. 候选 `CreditCode` 在主体性质未知时不是规范 identity；只有校验通过的 USCC 经 410 重新查询并匹配 `EntType`/`CreditCode` 后才可择取。
3. `KeyNo`、`QccCode`、排名、总数、订单号和 URL 永不成为 Customer ID、登记 scheme、tenant 或公共响应字段。
4. 410/735 中所有人员、股东、受益、职位、电话、邮箱、网站、企业画像、风险和未允许子对象在 adapter 返回核心前删除。
5. 已审定登记状态可映射，未知/新增/空白状态一律 `UNKNOWN`，且不会因为其他风险或注销字段变成 active。
6. `UpdatedDate` 不会覆盖 adapter `observedAt`，缺少合同 TTL 时不能生成虚假的 `expiresAt`。
7. 缺少持久化许可或 attribution 政策时 capability 至多为 `EPHEMERAL_ONLY`；缺少必需展示能力时直接 `NOT_READY`。
8. 公开状态码各组、未知码、超时、畸形 JSON、超限字符串/集合和部分响应都按第 8 节收敛，不透传消息或写 Customer。
9. 额度、并发、维护和认证失败不会重试风暴；110 冷却类结果不会被普通调用绕过。
10. 两个 tenant 共用 adapter 进程时，账号、策略、额度、缓存、locator 和错误审计按受治理 binding 隔离；普通请求不能选择账号。
11. URL/query、headers、异常、日志、trace、metric、事件和 Activity 中没有名称、USCC、地址、人员、key、Token、SecretKey、订单号或响应 body。
12. 供应商不可用、许可缺失或 adapter 禁用只关闭 B23；B06 创建、更新和查询继续独立工作。

fixture 只能证明 adapter contract 的缩减和失败关闭，不能证明真实许可、数据正确性、生产 QPS 或实际供应商响应兼容性。

## 10. 对 B23 的输入与剩余阻断项

B23-C 支持以下规划结论：

- 首期公共 profile 只保留规范登记身份、登记名称、粗粒度状态、带明确 kind 的可选成立日期、单一登记地址、来源/观测/到期语义；B23-XP 已移除没有跨来源共同值域的组织/legal-form 类型，且不新增扩展 map。
- 商业供应商的名称候选必须经过规范登记身份二次解析，供应商主键不能替代 jurisdiction/scheme/value。
- 人员数据必须在私有 adapter 白名单化时丢弃，而不是等核心或 UI 隐藏。
- adapter capability 只表达查询形态、候选上限和当前技术可用性；usage、许可、TTL 与 attribution readiness 由独立 tenant policy 提供，B23a 取最严交集。
- 公共错误只保留无结果、不支持、额度和不可用等安全类别；供应商认证、账号、地域、购买和诊断细节不公开。

以下事项仍阻断真实实现子批次：

1. B23-O/1、[B23-O/2](../B23-O-official-source-readiness.md)、B23-XI 与 B23-XP 已完成，B23-XF 也已执行开放/商业合成查询组合；Customer 身份占用、采用事务与 provenance 的实现级 MySQL fixture 仍未完成。
2. 企查查公开文档没有完整状态枚举，无法仅凭公开证据冻结 `ACTIVE`/`INACTIVE` 映射。
3. 没有经审查的当前完整用户协议与商务合同来证明 CRM 展示、逐字段择取、持久化、缓存、导出、attribution、保留、删除与地域权利；公开页当前仅显示新版本日期而没有可审查正文。
4. 原公开状态目录已不可从记录 URL 取得，也没有真实但非仓库化的私有 conformance fixture 来验证当前状态目录、schema 演进、错误 body、HTTP 行为、数值配额和 tenant/账号隔离。
